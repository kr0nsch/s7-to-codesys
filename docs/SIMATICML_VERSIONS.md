# Версии SimaticML: что подтверждено и чем

SimaticML — XML экспорта блоков TIA Portal Openness. Пространства имён тел и интерфейса различаются у
версий TIA только номером (`FlgNet/v4`, `FlgNet/v5`), разборщик `s7conv/frontends/simaticml.py` сравнивает
локальные имена элементов и принимает любую версию. Ниже — что именно проверено для каждой пары «версия ×
язык». Пока строка не подтверждена XSD своей версии или открытым экспортом, о ней в README написано «разбор
по пространству имён, не проверено».

Схемы XSD V15.1, V16…V21 лежат копиями в dotnetprojects/DotNetSiemensPLCToolBoxLibrary
(`externalDlls/siemens/V*/Schemas`, © Siemens AG, в git не кладутся); у V14 SP1 и V15 там только DLL, схем
нет. XSD без `targetNamespace`, поэтому перед проверкой пространство имён фрагмента снимается.

открытом экспорте совпадают. Структура фрагментов этих языков XSD V21 проверена.

## Что XSD не проверяет

- Словарь элементов LAD/FBD: имя `Part` — свободное `SimaticName`, имя пина — `xs:string`. Перевод
  держится на словаре [MAPPING_LADFBD.md](MAPPING_LADFBD.md) с уровнем подтверждения каждой строки.
- Внешнюю оболочку `Document`/`SW.Blocks.*`/`AttributeList`: её в XSD нет, форма повторяет открытые экспорты.
- `UId` у `StlStatement`: XSD V21 пишет «Not allowed in STL», а экспорт V18 (Smart_Factory) их содержит —
  разборщик их не читает и не требует.

## Как проверить свою выгрузку

1. `python -m s7conv check <каталог с *.xml>` — разбор без ошибок.
2. `python -m s7conv ir <файл.xml> --format json` — какие пространства имён встретились (`namespaces`).
3. Если пространство имён вашей версии в матрице не подтверждено — сравните отчёт конвертации с исходными
   сетями в TIA вручную и пришлите результат (`docs/BUILD_ERRORS.md`).
