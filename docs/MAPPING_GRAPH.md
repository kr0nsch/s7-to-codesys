# S7-GRAPH → ST-двойник и SFC CODESYS

Блок S7-GRAPH (FB с сетью `<Graph>` в SimaticML) переводится в два результата:

| Результат | Где | Когда | Чем проверен |
|---|---|---|---|
| ST-двойник — ФБ на ST с тем же интерфейсом | `src/POUs/Lang/Converted/<Блок>` (`build-corpus`), `<out>/src/…` (`convert`) | всегда | сценарии CSV (`stsim`, CODESYS), `s7conv equiv` против эталона GRAPH, многоцикловый набор `tests/POUs/Graph/<Блок>_SeqTest` |
| Вариант SFC — PLCopen XML: POU SFC `<Блок>_Sfc` и ФБ-обёртка `<Блок>` на ST | `plcopen/Lang/Converted/<Блок>.xml` (`build-corpus`), `<КАТАЛОГ>/<Блок>.xml` (`convert --plcopen КАТАЛОГ`) | если последовательность выражается в SFC (таблица ниже) | импорт скриптом, сборка и тот же набор `<Блок>_SeqTest` в CODESYS: `python tools_project/cds_plcopen.py test` |

Почему два: наладчик ищет неисправность по шагам, их времени и переходам в онлайне — в SFC это родное
([STRATEGIES.md](STRATEGIES.md)). Но SFC — графика: её не прогнать в `stsim`, не проверить RuSTy и
iec_checker, а diff PLCopen XML нечитаем. ST-двойник даёт всё это и служит эталоном для варианта SFC: оба
проходят один и тот же набор coUnit.

Стратегия блока в отчёте конвертации: `st + sfc` — построены оба, `st` — вариант SFC не построен (причина —
в предупреждении `build-corpus` и `convert --plcopen`).

## Что переводится

| GRAPH | ST-двойник | Вариант SFC | Правило |
|---|---|---|---|
| Шаг, начальный шаг (`Init="true"`) | статика `<Шаг>_X`, `<Шаг>_T`, `<Шаг>_Start` | `step`, `initialStep` | `graph.step` |
| Переход: сеть LAD/FBD с катушкой `TrCoil` | `xT<n>_Cond := выражение;`, `xT<n>_Fire := предшественники AND xT<n>_Cond AND NOT xGraphHold` | `transition`, условие — `inVariable` с выражением ST | `lad.graph_condition` (элемент уровня L — «требует проверки») |
| `#Шаг.X`, `#Шаг.T` в условиях | `<Шаг>_X`, `<Шаг>_T` | неявные переменные SFC `Шаг.x`, `Шаг.t` | — |
| Альтернативная ветвь (`AltBegin`/`AltEnd`) | левый переход приоритетнее: у правых `AND NOT xT<левый>_Fire` | `selectionDivergence`/`selectionConvergence` (CODESYS: первый слева) | `graph.alt_priority` — проверка |
| Параллельная ветвь (`SimBegin`/`SimEnd`) | переход включает все шаги ветви; переход схождения ждёт все шаги | `simultaneousDivergence`/`simultaneousConvergence` | — |
| Прыжок (`LinkType` `Jump`) | включение целевого шага | `jumpStep` | — |
| `N` на операнд | `IF X OR S0 THEN op := X; END_IF` (S0 — шаг выключился в этом вызове) | IEC N над флагом `x<Шаг>_N<k>`, в обёртке `op := флаг` (общий операнд нескольких шагов — ИЛИ) | `graph.action_n` |
| `S`, `R` на операнд | каждый вызов, пока шаг активен | IEC N над флагом, в обёртке `IF флаг THEN op := TRUE/FALSE` | `graph.action_sr` |
| `D`, `L` с временем | по времени шага: `op := X AND <Шаг>_T >= t` (D), `< t` (L) | IEC D/L над флагом — своим таймером `SFCActionControl` | `graph.timer_clock` — проверка |
| Событие `S1` с инструкцией SCL | один раз при активации | IEC P над флагом, инструкция — в обёртке | `graph.event` |
| Событие `S0` | один раз при выключении | не переносится — вариант SFC не строится | `graph.event` |
| `N` с инструкцией SCL без события | каждый вызов, пока шаг активен | не переносится: IEC-действие выполняется ещё раз после выключения шага | `graph.action_n` |
| Блокировка (`Interlock`, `IlCoil`), действия с `C` | `x<Шаг>_Il := условие`; действие с `C` — только при выполненном условии; переход не держит | то же в обёртке (`AND (условие)`) | `lad.graph_condition` |
| Контроль (`Supervision`, `SvCoil`) | защёлка `<Шаг>_SvErr`, пока шаг активен и условие выполнено; переходы из шага держатся до `ACK_EF` | защёлка в обёртке, вход SFC; условие перехода `AND NOT <Шаг>_SvErr` | `graph.supervision` — проверка |
| `ACK_EF` | сброс защёлок до переходов: в цикле квитирования переход возможен | то же в обёртке | — |
| `INIT_SQ` и первый вызов | начальные шаги включены, остальные выключены, защёлки сброшены, переходы держатся, пока `INIT_SQ = 1` | `SFCInit := INIT_SQ`; пока флаг поднят, обёртка считает начальный шаг активным, остальные — выключенными | — |
| `OFF_SQ` | все шаги выключены, переходы держатся | не переносится: вход обёртки не используется (пометка в отчёте `build-corpus`) | — |
| `ERR_FLT` | ИЛИ защёлок контроля | то же в обёртке | — |
| Постоянные операции после (`PostOperations`) | после последовательности | в обёртке после вызова SFC | — |
| Постоянные операции до (`PreOperations`) | до последовательности | не переносится — вариант SFC не строится | — |

Не переводится (в ST-двойнике — `MIGRATION-TODO` с правилом, вариант SFC не строится):

- события `V1`, `V0`, `L0`, `L1`, `A1`, `R1` — `graph.event_unsupported`;
- действия `ON`, `OFF`, таймеры и счётчики в действиях (`TL`, `TD`, `TR`, `TF`, `CS`, `CU`, `CD`, `CR`) —
  `graph.action_unsupported`;
- режимы и ручное управление (`SW_AUTO`, `SW_TAP`, `SW_TOP`, `SW_MAN`, `S_SEL`, `S_ON`, `S_OFF`, `S_PREV`,
  `S_NEXT`, `T_PUSH`, выходы `S_NO`, `S_MORE`, `S_ACTIVE`, `AUTO_ON` …, `HALT_SQ`, `EN_IL`, `EN_SV` …) —
  `graph.mode_unsupported`;
- предел времени шага `MaximumStepTime`, `WarningTime` — `graph.step_time_limits`;
- вторая и следующие последовательности одного блока — `graph.sequences`; время без помех `Si.U`, тексты
  сообщений и категории ProDiag.

## Порядок цикла ST-двойника

Допущение L18 ([ASSUMPTIONS.md](ASSUMPTIONS.md)); у каждого блока GRAPH — пометка `graph.cycle_order`.

1. Время вызова `tGraphNow := F_S7Now()`; состояние шагов прошлого вызова `x<Шаг>_Prev`.
2. `INIT_SQ` или первый вызов — начальное состояние; `OFF_SQ` — все шаги выключены; `xGraphHold` держит
   переходы в этом вызове.
3. `ACK_EF` сбрасывает защёлки контроля.
4. Время активных шагов: `<Шаг>_T := F_S7TimeDiff(tGraphNow, <Шаг>_Start)`.
5. Условия всех переходов по состоянию после шагов 2–4.
6. Срабатывание: все предшественники активны, условие истинно, нет `xGraphHold` и ошибки контроля
   предшественника; у альтернатив — приоритет левой.
7. Переключение: сначала выключаются предшественники всех сработавших переходов, затем включаются преемники.
8. События `S1`/`S0` по сравнению с прошлым вызовом; активация обнуляет время шага.
9. Контроль (защёлка) и блокировка активных шагов.
10. Действия шагов — в том же вызове, по состоянию после переключения.
11. `ERR_FLT`, постоянные операции после.

## Вариант SFC

- **Флаги вместо тел действий.** Каждое действие GRAPH — IEC-действие SFC над BOOL-флагом выхода SFC
  (`x<Шаг>_<Квалификатор><номер>`), контроль шага — флаг `x<Шаг>_Active`. Операнды, `S`/`R`, инструкции
  событий, защёлки и постоперации пишет обёртка по этим флагам: IEC-действие CODESYS выполняется ещё раз после
  выключения шага, и побочные эффекты в теле действия удвоились бы.
- **На вызов позже.** SFC CODESYS переключает шаги в конце своего цикла: действия нового шага видны со
  следующего вызова — на один вызов позже ST-двойника. Поэтому общий набор `<Блок>_SeqTest` многоцикловый:
  каждый шаг теста — `CYCLES` (3) вызова с одними входами, проверки — после них. Наборы сценариев CSV
  проверяют каждый вызов точно и прогоняются только на ST-двойнике.
- **`INIT_SQ`.** Пока `SFCInit = TRUE`, CODESYS держит начальный шаг, но не выполняет его действия; GRAPH
  (и ST-двойник) их выполняет. Обёртка поэтому подставляет `флаг OR INIT_SQ` для действий начального шага и
  `флаг AND NOT INIT_SQ` для остальных (проверено набором `InitResets` в CODESYS Control Win: без этого
  `xReady` при `INIT_SQ = 1` ложен).
- **Форма XML** — та, что принял импорт CODESYS 3.5.17.30: пространство имён `tc6_0200`, условие перехода —
  `inVariable` с выражением (элемент `<inline>` импорт пропускает), тип экземпляра SFC — `<derived name>`,
  настройки SFC — `addData` `sfcsettings` с флагом `SFCInit`; координаты 0,0. Библиотеку IecSfc CODESYS
  добавляет в проект сам при импорте (4.1.0.0).
- Вид диаграммы SFC в редакторе после импорта скриптом не проверялся — ручной шаг
  [MANUAL_STEPS.md](MANUAL_STEPS.md), 4.6.

## Чего проверка не доказывает

- **Блок GRAPH корпуса синтетический.** `samples/lang/FB_BackwashGraph.xml` собран `samples/lang/build_xml.py`
  по XSD Graph_v6: открытого экспорта GRAPH с лицензией нет. Имена катушек `TrCoil`, `SvCoil`, `IlCoil` и
  форма пустой сети условия взяты из образцов без лицензии — уровень L, пометка `vocab_unverified` у каждого
  перехода (допущение L17).
- **Эталон GRAPH — модель по руководствам.** Порядок цикла, `INIT_SQ`, квитирование и приоритет альтернатив
  (L18–L22) сверены с руководством S7-GRAPH V5.3 и документом «GRAPH в TIA Portal для S7-1500», не с CPU.
- **SFC и ST-двойник сверены набором, а не доказательством.** Набор `<Блок>_SeqTest` написан по описанию
  блока; поведение вне его тестов (например, `OFF_SQ` в варианте SFC) не сравнивается.
